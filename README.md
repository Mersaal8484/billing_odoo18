# Utility ERP

نظام ERP متكامل مبني على Odoo 16 مخصص لإدارة شركات توزيع الكهرباء، ويغطي دورة العمل الشاملة: المشتركين والعملاء، الشبكات الجغرافية والفنية (محطات، مغذيات، محولات، مسارات)، العدادات والمخزون، أوامر العمل الميدانية، القراءات، الفوترة الآجلة، التحصيل، وتطبيق قارئ العدادات الميداني وتكامل الرؤية الحاسوبية (AI Vision).

## نطاق الإصدار الحالي (V1)

- النظام مخصص حاليًا لشركة توزيع واحدة (Single Company).
- نظام الفوترة في هذا الإصدار آجل بالكامل (Postpaid).
- الفواتير التشغيلية مبنية على توريث أوامر البيع القياسية (`sale.order`)، والفواتير المالية على قيود وحركات الحسابات (`account.move`)، والمدفوعات على (`account.payment`).
- ترحيل البيانات ونماذج Staging مدمجة داخل `utility_core` (لا توجد وحدة منفصلة باسم `utility_migration`).
- بوابة المشتركين مدمجة داخل `utility_billing`.

## هيكل المشروع والمكونات

### 1. وحدات Odoo (Addons)

1. **`date_range`** — إدارة الفترات الزمنية والدورات المحاسبية ودورات الفوترة.
2. **`utility_core`** — النواة المركزية للنظام: البيانات الأساسية للعملاء والمشتركين، الهيكل الجغرافي والشبكي (منطقة ← فرع ← نطاق ← مكتب ← محطة تحويل ← مغذي ← محول ← مسار)، قوالب العقود والتعريفات، عدادات الكهرباء، نموذج القراءات الموحد `utility.reading`، ونماذج ترحيل البيانات (Data Migration Staging).
3. **`utility_inventory`** — جسر الربط المخزني: إدارة مخزون العدادات كأصول ومعدات تتبع الدفعات والأرقام التسلسلية (`stock.production.lot`)، أذون الصرف والتحويل، ومواءمة العهد وحالات العدادات.
4. **`utility_operations`** — العمليات والخدمات الميدانية: دورة حياة المشترك (تركيب، فحص، فصل، إعادة توصيل، إلغاء)، أوامر استبدال العدادات مع حفظ تسوية القراءات النهائية وتصفير العداد الجديد، ومتابعة حالات العبث والفاقد.
5. **`utility_billing`** — محرك الفوترة الآجلة والتحصيل: دورات القراءات (Reading Batches)، احتساب استهلاك الشرائح، احتساب الرسوم الإضافية والغرامات، إنشاء واعتماد الفواتير (`sale.order` / `account.move`)، معالجة الدفعات والتحصيل، وواجهات REST APIs للفوترة وتطبيق الميدان.
6. **`utility_meter_vision`** — وحدة الذكاء الاصطناعي والرؤية الحاسوبية: معالجة صور العدادات والتحقق الآلي من القراءات والتعرف على الأرقام وضمان سلامة الصور المرفوعة.

### 2. التطبيقات والخدمات المساندة

- **`mobile/`** — تطبيق الجوال الميداني (Flutter): تطبيق متكامل لمحصلي وقراء العدادات يدعم العمل دون اتصال (Offline-first)، التقاط القراءات مع الصور والإحداثيات الجغرافية، والمزامنة اللحظية مع خادم Odoo عبر REST APIs.
- **`meter-vision-service/`** — خدمة مستقلة لمعالجة صور العدادات بالذكاء الاصطناعي (YOLO / Computer Vision).

## التشغيل والتثبيت عبر Odoo CLI

أضف مسار المشروع إلى `addons_path` في ملف الإعدادات `odoo.conf` أو مرره عبر سطر الأوامر:

```bash
# تثبيت الوحدات الأساسية
odoo-bin -d <database> -i utility_core --stop-after-init
odoo-bin -d <database> -i utility_inventory --stop-after-init
odoo-bin -d <database> -i utility_operations --stop-after-init
odoo-bin -d <database> -i utility_billing --stop-after-init

# تثبيت وحدة الرؤية الحاسوبية (اختياري)
odoo-bin -d <database> -i utility_meter_vision --stop-after-init
```

عند تحديث ملفات أي وحدة:

```bash
odoo-bin -d <database> -u utility_billing --stop-after-init
```

## دورات العمل الرئيسية

### 1. دورة حياة القراءات (Reading Lifecycle)
```text
draft → under_review → approved → billed
```
- يتم إدخال القراءة إما يدوياً أو عبر المزامنة من تطبيق الميدان (`mobile/`).
- تمر القراءات غير النمطية بمرحلة مراجعة وتدقيق مع إمكانية التحقق من صورة العداد وإحداثيات الموقع.
- عند الاعتماد والفوترة، تتحول القراءة إلى حالة `billed` وترتبط بأمر الفاتورة. وفي حال الرفض تعود إلى `draft` للتصحيح.

### 2. الفوترة الآجلة (Postpaid Billing)
- تعتمد الفاتورة على نموذج `sale.order` مع حقول إضافية لإدارة دورة حياة الفاتورة الكهربائية عبر `bill_state` (`draft → confirmed → sent → paid → overdue → cancelled`).
- توزيع الاستهلاك على الشرائح يتم آلياً وفق إعدادات قالب العقد (`utility.contract.template`).
- عند الاعتماد والترحيل المحاسبي، يتم إصدار فاتورة عميل قياسية (`account.move`).
- تُسجل السدادات والدفعات عبر قيود المقبوضات القياسية (`account.payment`).

### 3. إدارة وحركة العدادات (Meters & Inventory)
- العداد يمثل السجل التشغيلي الفني في `utility.meter`.
- الحركة الفيزيائية والمخزنية تنعكس كعمليات نقل مخزني قياسية (`stock.picking`) مرتبطة بدفعات الأرقام التسلسلية (`stock.production.lot`).
- في عمليات الاستبدال، يتم إثبات قراءة الرفع النهائية، وتصفير عداد البديل، وضمان سلامة السجلات محاسبياً وتشغيلياً.

## النماذج الرئيسية في النظام

| المجال | النموذج في Odoo | الوصف |
|---|---|---|
| المشترك / العميل | `utility.customer` | بيانات المشترك، الموقع، الرقم المرجعي، والحساب |
| العداد الكهربائي | `utility.meter` | السجل التشغيلي للعداد، الطراز، والحالة الفنية |
| القراءة الموحدة | `utility.reading` | سجل القراءة، الاستهلاك، الصورة، وحالة الاعتماد |
| دفعة القراءات | `utility.reading.batch` | مسار أو دورة قراءة مجدولة لمجموعة عدادات |
| قارئ العدادات | `utility.meter.reader` | ملف وسجل قارئ العداد وربطه بالمسارات والمستخدمين |
| قوالب العقود والتعريفات | `utility.contract.template` | هيكل التعريفة، الشرائح، ورسوم الخدمة |
| دورات الفترات | `date.range` | الفترات الشهرية ونصف الشهرية المعتمدة للفوترة |
| الفاتورة التشغيلية | `sale.order` (Inherited) | الفاتورة الآجلة وحساب الشرائح والاستهلاك |
| الفاتورة المالية | `account.move` | القيد والفاتورة المحاسبية الرسمية |
| الدفعات والسداد | `account.payment` | سندات التحصيل والمقبوضات |
| العمليات والخدمات | `utility.customer.lifecycle` | أوامر التركيب، الفحص، الفصل، وإعادة الخدمة |
| فحص صور العدادات | `meter.vision.request` | طلبات التحقق الآلي بالرؤية الحاسوبية من قراءات العداد |

## واجهات التكامل (APIs)

توفر `utility_billing` واجهات REST شاملة تحت المسار:
```text
/api/v1/utility/billing/*
```
وتشمل:
- مصادقة مستخدمي تطبيق قارئ العدادات.
- سحب مسارات وقوائم المشتركين والعدادات المخصصة لكل قارئ.
- رفع القراءات مع الصور والإحداثيات الجغرافية (مع التحقق من منع التكرار).
- استعلام فواتير المشتركين وحالات السداد.
- نقاط استقبال قراءات العدادات الذكية (AMI Callback).
